<h1 align="center">FlowCheck Local</h1>

<p align="center">Превратите браузерные проверки от AI-агента в повторяемые тесты с доказательствами результата.</p>

<p align="center"><a href="README.md">English</a> · <a href="docs/scenario-format.md">Формат сценариев</a> · <a href="README.md#connect-an-ai-agent-with-mcp">Настройка MCP</a></p>

**Агент изменил интерфейс. Пользовательский сценарий всё ещё работает?**

FlowCheck запускает JSON-сценарий в Chromium и сохраняет результат, скриншоты, Playwright trace и JUnit XML. Проверьте шаги, положите сценарий в Git и повторяйте ту же проверку после следующих изменений через CLI или MCP.

Runner работает на localhost и не требует аккаунта FlowCheck, API-ключа или вызова модели. Сценарий пишете вы или ваш агент; во время выполнения runner не придумывает новые шаги и не меняет проверки.

## Быстрый запуск

Требуется Node.js 22.18+ на macOS или Linux.

```bash
git clone https://github.com/kadessovb02/flowcheck.git
cd flowcheck
npm ci
npx playwright install chromium
npm run quickstart
```

Команда запустит встроенный demo-сайт на порту **4173**, создаст workspace Acme, проверит подтверждение и URL, сохранит результаты в `.flowcheck/runs/` и остановит сервер. Для просмотра браузера используйте `npm run quickstart -- --headed`.

Если на Linux не хватает системных библиотек Chromium: `npx playwright install --with-deps chromium`.

## Посмотрите, как находится ошибка

```bash
npm run quickstart -- --broken
```

В этом режиме demo-приложение выдаёт ошибку создания workspace. **Сценарий проверки остаётся прежним.** Шаг `confirmation` падает, следующий шаг не выполняется, сохраняются скриншот и trace. `FAILED` и код завершения **1** здесь ожидаемы.

![Реальный скриншот упавшего демо: email замаскирован, приложение показывает ошибку создания workspace](docs/assets/demo-failure.png)

Запустите команду без `--broken`, и тот же сценарий пройдёт.

## Зачем это, если есть Playwright?

| Инструмент | Когда подходит |
|---|---|
| [Playwright Test](https://playwright.dev/docs/intro) | Нужен полноценный набор тестов на языке программирования, фикстуры, разные браузеры и параллельные запуски. |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | Агент исследует браузер и выбирает действия по ходу работы. |
| **FlowCheck Local** | Нужен небольшой, заранее проверенный JSON-сценарий, который повторяется одним запуском через CLI или MCP и оставляет локальные доказательства результата. |

FlowCheck использует Playwright. Если существующий набор тестов вас устраивает, переносить его не нужно. Здесь фокус на коротких smoke-проверках: регистрация, отправка формы, навигация.

## Собственный сценарий

```bash
npm run flowcheck -- init flowcheck.scenario.json
```

Запустите своё приложение и отредактируйте `baseUrl`, шаги и ожидаемый результат в созданном файле. Затем:

```bash
npm run flowcheck -- validate flowcheck.scenario.json
npm run flowcheck -- run flowcheck.scenario.json --headed
```

Рабочий пример для встроенного демо есть в [английском README](README.md#run-your-own-scenario). Поддерживаются переходы, клики, заполнение, выбор, checkbox, клавиши, ожидания и проверки текста, URL и видимости. Подробности — в [документации формата](docs/scenario-format.md).

## Результаты запуска

```text
.flowcheck/runs/<run-id>/
├── report.json      # машинный отчёт
├── junit.xml        # результат для CI
├── trace.zip        # Playwright trace, если включён
└── *-failed.png     # скриншот ошибки, если включён и удалось сохранить
```

Коды завершения: `0` — успех, `1` — провал проверки, `2` — некорректный ввод или ошибка запуска. Для просмотра trace подставьте путь из вывода команды:

```bash
npx playwright show-trace .flowcheck/runs/<run-id>/trace.zip
```

## Статус и ограничения

Это **ранняя предварительная версия**: Chromium на macOS и Linux, последовательные шаги. До стабильного релиза формат может меняться. Установка пока из исходников; установка через npm ещё не предусмотрена.

Открыты формат сценариев, валидатор, runner, CLI, MCP-сервер и сохранение результатов. Runner работает самостоятельно. Облачное планирование, расписания и командные процессы не входят в этот репозиторий. [Архитектура](docs/architecture.md).

## Безопасность

Запускайте проверки только против систем, на тестирование которых есть разрешение. Секреты можно получать из переменных окружения. Чувствительные значения `fill` скрываются в данных шагов отчёта; поля на скриншотах маскируются явно заданными локаторами.

Маски скриншотов **не очищают trace-файлы, URL и сообщения об ошибках**. Результаты могут содержать чувствительные данные. Подробности: [SECURITY.md](SECURITY.md).
