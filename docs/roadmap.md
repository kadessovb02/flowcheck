# Roadmap after runner and CI suite

This is a sequence of proposed work, not shipped functionality. Finish and verify the runner/CI iteration before starting the next stage.

1. **Public TypeScript SDK.** Define stable `validateScenario`, `runScenario`, and `runSuite` exports and declaration files. Keep imports free of CLI/MCP startup, browser download, stdout, exit-code, and file side effects. Ready when an installed tarball passes an SDK import and run test outside this repository.
2. **Reporters and Playwright compatibility.** Put JSON, JUnit, and GitHub summary behind one small interface using the same result model. Investigate how FlowCheck checks can coexist with Playwright Test suites. Ready when reporter contract tests agree on passed/failed/errored/skipped and a documented integration path works without duplicating Playwright fixtures, sharding, or retries.
3. **Change review for checks.** Compare an executed scenario with a trusted Git baseline and report removed assertions, changed expectations, locator/scope/exact changes, URL patterns, and step order. Classify removal, changed condition, possible weakening, and human-review requirement separately. The PR must not choose its own baseline; hashes identify content, not approval. Ready when a read-only diff is tied to the exact executed scenario and runtime overrides. Define trust and fork-PR policy before any blocking gate.
4. **Optional HTTP adapter, only if needed.** Add one only for an integration that CLI, SDK, and MCP cannot serve. It should wrap the same core, bind localhost by default, require explicit authorization, bound resources and network access, support cancellation, and document artifact access. Ready when the concrete use case and threat model are reviewed; no server is planned now.
