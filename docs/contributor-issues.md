# Proposed contributor issues

These are drafts for review; none has been published. Complexity is relative to this repository.

1. **Test URL assertions after client-side redirects.** Problem: timing variants beyond `pushState` can regress. Code: `tests/runner.e2e.test.ts`, `src/runner.ts`. Expected: delayed `replaceState` and navigation pass within timeout, timeout fails. Constraint: no fixed runner sleep or scenario retry. Acceptance: both paths covered. Verify: `npm run test:e2e`. Complexity: small.
2. **Check visible text in nested components.** Problem: nested text and hidden siblings need documented behavior. Code: `src/runner.ts`, `tests/runner.e2e.test.ts`. Expected: one visible match in the chosen scope. Constraint: no universal `.first()`. Acceptance: tests for nested/hidden/duplicate cases. Verify: `npm run test:e2e`. Complexity: small.
3. **Strengthen schema parity fixtures.** Problem: runtime-only URL and cross-step rules are easy to miss. Code: `src/schema.ts`, `tests/schema.unit.test.ts`. Expected: explicit fixtures showing MCP schema and validator agree where JSON Schema can express the rule. Constraint: preserve DSL v1. Acceptance: representative valid/invalid fixtures and documented runtime-only checks. Verify: `npm run test:unit`. Complexity: medium.
4. **Test CLI flag applicability.** Problem: flags may be accepted by commands that ignore them. Code: `src/cli.ts`, CLI e2e tests. Expected: clear error for unsupported command/flag combinations. Constraint: keep documented CLI calls working. Acceptance: matrix for common flags and exit code 2. Verify: `npm run test:e2e`. Complexity: small.
5. **Improve suite file discovery diagnostics.** Problem: inaccessible directories and malformed globs need precise errors. Code: `src/suite.ts`, `tests/suite.e2e.test.ts`. Expected: file-specific error and deterministic ordering. Constraint: no symlink traversal outside chosen root without explicit policy. Acceptance: fixtures for empty, unreadable, and nested paths. Verify: `npm run test:e2e`. Complexity: medium.
6. **Document safe evidence upload choices.** Problem: users may upload traces or screenshots with private data. Code: `README.md`, `docs/scenario-format.md`, `examples/github-actions/flowcheck.yml`. Expected: concise artifact review and synthetic example. Constraint: do not claim screenshot masks sanitize traces, URLs, or errors. Acceptance: copyable example lists only reviewed files. Verify: documentation review and YAML parse. Complexity: small.
7. **Add a GitLab CI recipe.** Problem: teams outside GitHub need an equivalent suite command. Code: new example under `examples/`, link from `README.md`. Expected: readiness timeout, exit-code preservation, reviewed artifacts. Constraint: reuse CLI, no core reporter fork. Acceptance: recipe tested in a GitLab runner or clearly marked unverified. Verify: runner log and a synthetic app. Complexity: medium.
8. **Define SDK import safety tests.** Problem: future public exports could trigger CLI/MCP side effects. Code: `scripts/test-package.mjs`, future SDK entrypoint. Expected: importing installed package does no I/O or browser setup. Constraint: test tarball outside checkout. Acceptance: isolated import test covering stdout/files/exit code. Verify: `npm run test:package`. Complexity: medium.
9. **Reporter contract fixture set.** Problem: JSON, JUnit, and summary can diverge as result types evolve. Code: `src/runner.ts`, `src/suite.ts`, `src/summary.ts`, tests. Expected: all four statuses map consistently. Constraint: do not invent a broad plugin system. Acceptance: shared fixtures for assertion failure, skipped, and setup error. Verify: `npm run check`. Complexity: medium.
10. **Prototype a read-only scenario diff.** Problem: changes to checks are hard to review in PRs. Code: future comparison module and tests. Expected: categories for removed assertion, changed condition, possible weakening, and human review. Constraint: trusted baseline outside the PR; no approval boolean or blocking gate. Acceptance: fixture diffs tied to exact scenario digest. Verify: unit tests and manual diff review. Complexity: large; not a good first issue.
